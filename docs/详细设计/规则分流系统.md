# 规则分流系统详细设计

## 1. 概述

规则分流系统是 Prism 的核心功能之一，用于根据连接的各种属性（域名、IP、端口、进程等）进行流量分类和路由决策。本文档详细说明规则分流系统的设计和实现。

## 2. 系统架构

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    规则分流引擎                          │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │
│  │  规则解析器  │  │  规则匹配器  │  │  动作执行器  │ │
│  └──────────────┘  └──────────────┘  └──────────────┘ │
│          │                  │                  │        │
│          ▼                  ▼                  ▼        │
│  ┌──────────────────────────────────────────────────┐  │
│  │              规则存储与索引                       │  │
│  └──────────────────────────────────────────────────┘  │
│                                                          │
└─────────────────────────────────────────────────────────┘
                          │
                          ▼
        ┌─────────────────────────────────────┐
        │      外部数据源                      │
        ├─────────────────────────────────────┤
        │  • GeoIP 数据库                     │
        │  • ASN 数据库                       │
        │  • 规则文件                         │
        └─────────────────────────────────────┘
```

### 2.2 模块职责

#### 规则解析器 (Parser)
- 解析规则字符串/文件
- 验证规则格式
- 创建规则对象

#### 规则匹配器 (Matcher)
- 匹配连接元数据
- 执行规则判断逻辑
- 返回匹配结果

#### 动作执行器 (Action Handler)
- 根据规则动作执行相应操作
- 支持 PROXY、DIRECT、REJECT 等动作

#### 规则存储与索引
- 存储已解析的规则
- 提供高效的规则查找
- 支持规则优先级

## 3. 核心数据结构

### 3.1 规则接口

```go
type Rule interface {
    Type() RuleType           // 返回规则类型
    Match(*Metadata) bool     // 判断是否匹配
    Action() ActionType       // 返回规则动作
    Payload() string          // 返回规则载荷
    String() string           // 返回字符串表示
}
```

### 3.2 连接元数据

```go
type Metadata struct {
    // 网络信息
    Network     string       // tcp, udp
    Type        string       // http, https, socks5
    SrcIP       netip.Addr   // 源 IP
    DstIP       netip.Addr   // 目标 IP
    SrcPort     uint16       // 源端口
    DstPort     uint16       // 目标端口

    // 域名信息
    Host        string       // 主机名
    Domain      string       // 规范化域名

    // GeoIP 信息
    DstGeoIP    *GeoIPInfo   // 目标 IP 的 GeoIP 信息
    SrcGeoIP    *GeoIPInfo   // 源 IP 的 GeoIP 信息

    // 进程信息
    ProcessName string       // 进程名称
    ProcessPath string       // 进程路径

    // 其他信息
    UID         uint32       // 用户 ID
    InboundName string       // 入站名称
}
```

## 4. 匹配算法

### 4.1 域名匹配

#### 精确匹配 (DOMAIN)
```go
func (d *Domain) Match(metadata *Metadata) bool {
    // 规范化为小写后精确比较
    return metadata.Domain == d.domain
}
```

**时间复杂度**: O(1)
**空间复杂度**: O(1)

#### 后缀匹配 (DOMAIN-SUFFIX)
```go
func (d *DomainSuffix) Match(metadata *Metadata) bool {
    domain := metadata.Domain
    suffix := d.suffix

    // 精确匹配
    if domain == suffix {
        return true
    }

    // 后缀匹配（必须是完整的子域名）
    if strings.HasSuffix(domain, "."+suffix) {
        return true
    }

    return false
}
```

**时间复杂度**: O(n)，n 为域名长度
**空间复杂度**: O(1)

#### 关键字匹配 (DOMAIN-KEYWORD)
```go
func (d *DomainKeyword) Match(metadata *Metadata) bool {
    return strings.Contains(metadata.Domain, d.keyword)
}
```

**时间复杂度**: O(n*m)，n 为域名长度，m 为关键字长度
**空间复杂度**: O(1)

#### 正则匹配 (DOMAIN-REGEX)
```go
func (d *DomainRegex) Match(metadata *Metadata) bool {
    return d.pattern.MatchString(metadata.Domain)
}
```

**时间复杂度**: 取决于正则表达式复杂度
**空间复杂度**: O(1)

**性能建议**:
- 优先使用精确匹配和后缀匹配
- 避免过度使用正则匹配
- 将常用规则放在前面

### 4.2 IP 匹配

#### CIDR 匹配
```go
func (i *IPCIDR) Match(metadata *Metadata) bool {
    if !metadata.DstIP.IsValid() {
        return false
    }

    // IPv4/IPv6 版本检查
    if i.isIPv6 != metadata.DstIP.Is6() {
        return false
    }

    return i.prefix.Contains(metadata.DstIP)
}
```

**时间复杂度**: O(1)
**空间复杂度**: O(1)

#### GeoIP 匹配
```go
func (g *GEOIP) Match(metadata *Metadata) bool {
    // 优先使用缓存的 GeoIP 信息
    if metadata.DstGeoIP != nil {
        return strings.EqualFold(
            metadata.DstGeoIP.CountryCode,
            g.countryCode
        )
    }

    // 查询 GeoIP 数据库
    if metadata.DstIP.IsValid() {
        info := queryGeoIP(metadata.DstIP.String())
        if info != nil {
            // 缓存查询结果
            metadata.DstGeoIP = convertToGeoIPInfo(info)
            return strings.EqualFold(
                info.CountryCode,
                g.countryCode
            )
        }
    }

    return false
}
```

**时间复杂度**: O(log n)，n 为 GeoIP 数据库大小
**空间复杂度**: O(1)

**优化策略**:
- 缓存 GeoIP 查询结果
- 使用高效的 GeoIP 数据库（如 MaxMind MMDB）
- 考虑使用 LRU 缓存减少重复查询

### 4.3 端口匹配

```go
func (p *Port) Match(metadata *Metadata) bool {
    var port uint16
    if p.isDst {
        port = metadata.DstPort
    } else {
        port = metadata.SrcPort
    }

    // 检查单个端口
    for _, p := range p.ports {
        if port == p {
            return true
        }
    }

    // 检查端口范围
    for _, r := range p.portRanges {
        if port >= r[0] && port <= r[1] {
            return true
        }
    }

    return false
}
```

**时间复杂度**: O(n+m)，n 为单个端口数量，m 为端口范围数量
**空间复杂度**: O(n+m)

**优化建议**:
- 合并重叠的端口范围
- 使用二分查找优化大量端口规则

## 5. 规则解析

### 5.1 规则语法

```
规则格式: TYPE,PAYLOAD,ACTION[,OPTIONS]
```

#### 示例
```text
# 域名规则
DOMAIN,google.com,PROXY
DOMAIN-SUFFIX,google.com,PROXY
DOMAIN-KEYWORD,google,PROXY
DOMAIN-REGEX,^.*\.cn$,DIRECT

# IP 规则
IP-CIDR,192.168.0.0/16,DIRECT
IP-CIDR6,2001:db8::/32,PROXY
GEOIP,CN,DIRECT
IP-ASN,13335,PROXY

# 端口规则
DST-PORT,80,DIRECT
DST-PORT,443,8000-9000,PROXY

# 进程规则
PROCESS-NAME,chrome,PROXY
PROCESS-PATH,/usr/bin/wget,DIRECT

# 匹配所有
MATCH,PROXY
```

### 5.3 错误处理

| 错误类型 | 说明 | 示例 |
|---------|------|------|
| ErrInvalidRule | 规则格式错误 | `DOMAIN` (缺少参数) |

## 6. 性能优化

### 6.1 规则顺序优化

**原则**: 将匹配频率高的规则放在前面

```text
# 推荐
DOMAIN,frequently-visited.com,PROXY      # 高频访问
DOMAIN-SUFFIX,popular-site.com,DIRECT    # 常用网站
IP-CIDR,192.168.0.0/16,DIRECT           # 内网地址
# ... 其他规则
MATCH,PROXY                              # 兜底规则

# 不推荐
DOMAIN-REGEX,^very-rare-pattern$,PROXY   # 低频匹配
DOMAIN,frequently-visited.com,PROXY      # 高频访问
```

### 6.2 规则类型选择

| 优先级 | 规则类型 | 性能 | 适用场景 |
|--------|---------|------|---------|
| 1 | DOMAIN | ⭐⭐⭐⭐⭐ | 已知完整域名 |
| 2 | DOMAIN-SUFFIX | ⭐⭐⭐⭐ | 匹配子域名 |
| 3 | IP-CIDR | ⭐⭐⭐⭐ | IP 范围匹配 |
| 4 | GEOIP | ⭐⭐⭐ | 国家/地区分流 |
| 5 | DOMAIN-KEYWORD | ⭐⭐ | 模糊匹配 |
| 6 | DOMAIN-REGEX | ⭐ | 复杂模式匹配 |

### 6.3 缓存策略

#### 元数据缓存
```go
type Metadata struct {
    // ...
    DstGeoIP *GeoIPInfo  // 缓存 GeoIP 查询结果
    SrcGeoIP *GeoIPInfo  // 缓存源 IP 的 GeoIP
}
```

#### 规则缓存
- 预编译正则表达式
- 缓存 GeoIP 查询结果
- 使用 sync.Pool 减少对象分配

### 6.4 并发优化

- 规则列表使用 sync.RWMutex 保护
- GeoIP 提供者使用读写锁
- 支持并发规则匹配

## 7. 扩展性设计

### 7.1 自定义规则类型

实现 `Rule` 接口即可添加自定义规则：

```go
type CustomRule struct {
    base
    // 自定义字段
}

func (c *CustomRule) Match(metadata *Metadata) bool {
    // 自定义匹配逻辑
    return true
}
```

### 7.2 GeoIP 提供者

支持自定义 GeoIP 数据源：

```go
rules.SetGeoIPProvider(func(ip string) *prism.GeoIP {
    // 自定义 GeoIP 查询逻辑
    return queryFromCustomSource(ip)
})
```

### 7.3 动作扩展

当前支持的动作：
- `PROXY`: 使用代理
- `DIRECT`: 直接连接
- `REJECT`: 拒绝连接
- `REJECT-DROP`: 拒绝并丢弃

可通过扩展 `ActionType` 添加更多动作。

## 9. 使用示例

### 9.1 基本用法

```go
// 创建规则
rule, _ := rules.ParseRule("DOMAIN,google.com,PROXY")

// 匹配元数据
metadata := &rules.Metadata{
    Host: "google.com",
}

if rule.Match(metadata) {
    fmt.Println("匹配成功:", rule.Action())
}
```

### 9.2 规则链匹配

```go
// 加载规则文件
rules, _ := rules.LoadRulesFromFile("rules.txt")

// 匹配第一个符合的规则
metadata := &rules.Metadata{
    Host:    "www.google.com",
    DstPort: 443,
}

if rule, ok := rules.MatchFirst(rules, metadata); ok {
    fmt.Println("匹配规则:", rule)
    fmt.Println("执行动作:", rule.Action())
}
```

### 9.3 集成 GeoIP

```go
// 设置 GeoIP 提供者
reader, _ := geoip.NewReader("geoip.mmdb")
rules.SetGeoIPProvider(func(ip string) *prism.GeoIP {
    info, _ := reader.LookupString(ip)
    return info
})

// 使用 GeoIP 规则
rule, _ := rules.ParseRule("GEOIP,CN,DIRECT")
```

## 11. 故障排查

### 11.1 常见问题

#### 规则不生效
- 检查规则语法是否正确
- 确认规则顺序（是否被前面的规则覆盖）
- 验证元数据是否包含必要信息

#### GeoIP 规则不匹配
- 检查是否设置了 GeoIP 提供者
- 确认 GeoIP 数据库是否存在
- 验证 IP 地址是否有效

#### 性能问题
- 减少正则表达式规则
- 优化规则顺序
- 使用规则缓存

### 11.2 调试技巧

