# 数据库设计规范

## 1. 时间字段规范

### 1.1 字段类型
- **所有时间字段必须使用 `TIMESTAMP` 类型**
- 禁止使用 `DATETIME`、`DATE`、`TIME` 等其他时间类型
- 禁止使用字符串类型存储时间

### 1.2 标准时间字段
每个表必须包含以下标准时间字段：

```sql
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,  -- 创建时间
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,  -- 更新时间
deleted_at TIMESTAMP,                            -- 软删除时间（可选）
```

### 1.3 业务时间字段
业务相关的时间字段也必须使用 `TIMESTAMP`：

```sql
expire_at TIMESTAMP,           -- 到期时间
last_update_at TIMESTAMP,      -- 上次更新时间
next_update_at TIMESTAMP,      -- 下次更新时间
tested_at TIMESTAMP,           -- 测试时间
executed_at TIMESTAMP,         -- 执行时间
```

## 2. 索引设计规范

### 2.1 软删除索引
- **所有索引必须包含 `deleted_at` 字段**（如果表有 `deleted_at` 字段）
- 确保查询时能够利用索引过滤已删除的记录

#### 正确示例
```sql
INDEX idx_enabled (enabled, deleted_at),
INDEX idx_type (type, deleted_at),
INDEX idx_score (score DESC, deleted_at)
```

#### 错误示例
```sql
INDEX idx_enabled (enabled),          -- ❌ 缺少 deleted_at
INDEX idx_type (type),                -- ❌ 缺少 deleted_at
```

### 2.2 复合索引顺序
- 高选择性字段在前
- 范围查询字段在后
- `deleted_at` 始终放在最后

```sql
INDEX idx_user_status (user_id, status, deleted_at),  -- ✅ 正确
INDEX idx_date_range (start_date, end_date, deleted_at)  -- ✅ 正确
```

## 3. 数据类型规范

### 3.1 禁止使用基本类型指针
在 Go 结构体中：
- **禁止使用 `*int64`、`*string`、`*bool`、`*float64` 等基本类型指针**
- **允许使用 struct 类型指针**

#### 正确示例
```go
type User struct {
    ID        int64     `db:"id"`           // ✅ 基本类型不用指针
    Name      string    `db:"name"`         // ✅ 基本类型不用指针
    Age       int       `db:"age"`          // ✅ 基本类型不用指针
    CreatedAt time.Time `db:"created_at"`   // ✅ time.Time 是 struct，可以不用指针
    DeletedAt *time.Time `db:"deleted_at"`  // ✅ struct 可以用指针表示 NULL
    Profile   *Profile  `db:"-"`            // ✅ struct 类型可以用指针
}
```

#### 错误示例
```go
type User struct {
    ID        *int64    `db:"id"`           // ❌ 禁止基本类型指针
    Name      *string   `db:"name"`         // ❌ 禁止基本类型指针
    Age       *int      `db:"age"`          // ❌ 禁止基本类型指针
}
```

### 3.2 NULL 值处理
对于可能为 NULL 的字段：
- 基本类型：使用 `sql.NullInt64`、`sql.NullString` 等
- 时间类型：使用 `*time.Time` 或 `sql.NullTime`
- Struct 类型：可以使用指针

```go
type Node struct {
    ID          int64          `db:"id"`
    Name        string         `db:"name"`
    DelayAvg    sql.NullInt64  `db:"delay_avg"`    // ✅ 可能为 NULL
    TestedAt    *time.Time     `db:"tested_at"`    // ✅ 可能为 NULL
    DeletedAt   *time.Time     `db:"deleted_at"`   // ✅ 可能为 NULL
}
```

## 4. 表设计规范

### 4.1 主键设计
- 使用自增 ID 或 SHA256 哈希作为主键
- 自增 ID 使用 `BIGINT AUTO_INCREMENT`
- 哈希 ID 使用 `VARCHAR(64)`

```sql
-- 自增主键
id BIGINT AUTO_INCREMENT PRIMARY KEY,

-- 哈希主键
id VARCHAR(64) PRIMARY KEY,  -- SHA256(URL) 或 SHA256(配置)
```

### 4.2 软删除
- 使用 `deleted_at TIMESTAMP` 字段实现软删除
- 所有查询都必须过滤 `deleted_at IS NULL`
- 定期清理软删除的数据（如 7 天后硬删除）

### 4.3 外键约束
- 使用外键保证数据完整性
- 级联删除使用 `ON DELETE CASCADE`
- 级联更新使用 `ON UPDATE CASCADE`

```sql
FOREIGN KEY (node_id) REFERENCES nodes(id) ON DELETE CASCADE,
FOREIGN KEY (subscription_id) REFERENCES subscriptions(id) ON DELETE CASCADE
```

## 5. 字段命名规范

### 5.1 命名风格
- 使用 snake_case 命名（全小写，下划线分隔）
- 禁止使用驼峰命名（camelCase）
- 禁止使用帕斯卡命名（PascalCase）

### 5.2 常用后缀
- `_id`: ID 字段
- `_at`: 时间字段
- `_count`: 计数字段
- `_url`: URL 字段
- `_path`: 路径字段
- `_type`: 类型字段
- `_status`: 状态字段

### 5.3 布尔字段
- 使用 `is_`、`has_`、`can_` 等前缀
- 例如：`is_enabled`, `has_children`, `can_delete`

```sql
enabled BOOLEAN DEFAULT true,        -- ✅ 简单布尔值
is_builtin BOOLEAN DEFAULT false,    -- ✅ 使用 is_ 前缀
has_parent BOOLEAN DEFAULT false,    -- ✅ 使用 has_ 前缀
```

## 6. 性能优化规范

### 6.1 分表策略
超过千万级数据的表考虑分表：
- 按时间分表（如按月、按年）
- 按哈希分表（如按用户 ID）
- PostgreSQL 使用声明式分区

### 6.2 索引优化
- 频繁查询的字段建立索引
- 避免过多索引（影响写入性能）
- 定期分析索引使用情况，删除无效索引

### 6.3 查询优化
- 避免 `SELECT *`，明确指定需要的字段
- 使用 `LIMIT` 限制结果集大小
- 复杂查询使用 `EXPLAIN` 分析执行计划

## 7. 数据库选型建议

### 7.1 SQLite
- 适用场景：单机部署、数据量 < 1000万
- 优点：零配置、轻量级、嵌入式
- 限制：并发写入受限

### 7.2 MySQL
- 适用场景：中小企业、数据量 < 1亿
- 优点：成熟稳定、生态丰富
- 推荐引擎：InnoDB

### 7.3 PostgreSQL
- 适用场景：企业级应用、复杂查询、地理数据
- 优点：功能强大、支持 JSONB、全文搜索、地理扩展
- 特性：声明式分区、流复制、多种索引类型

## 8. 迁移规范

### 8.1 版本控制
- 所有数据库变更必须通过迁移脚本
- 迁移脚本按时间戳命名：`20250101120000_create_users.sql`
- 每个迁移必须可回滚

### 8.2 迁移内容
- 包含 UP（升级）和 DOWN（回滚）脚本
- 添加注释说明变更原因
- 测试环境验证后再应用到生产环境

## 9. 违规检查清单

在提交代码前，必须检查：
- [ ] 所有时间字段是否使用 `TIMESTAMP`
- [ ] 所有索引是否包含 `deleted_at`（如果表有软删除）
- [ ] Go 结构体是否使用了基本类型指针
- [ ] 是否有缺失的外键约束
- [ ] 字段命名是否符合 snake_case 规范
- [ ] 是否添加了必要的索引
- [ ] 是否有性能隐患（如缺少索引的大表查询）
