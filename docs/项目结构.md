## 二、目录说明

### 2.1 核心目录

#### cmd/
**用途**: 应用程序入口点（只包含 Go 文件，不包含子目录）

**文件说明**:
- `server.go`: 主服务器程序，启动 HTTP API、SOCKS5 代理等服务
- `cli.go`: 命令行工具，用于管理订阅、测试节点等操作（可选）

**原则**:
- 文件命名清晰，一个文件对应一个可执行程序
- 保持简洁，主要逻辑在 internal 中
- 只负责程序初始化和启动
- 通过 Makefile 分别构建不同的可执行文件

**构建示例**:
```bash
# 构建服务器
go build -o bin/prism-server ./cmd/server.go

# 构建命令行工具
go build -o bin/prism-cli ./cmd/cli.go
```

#### shared/
**用途**: 前端共享代码（Web 和 Desktop 共用）

**包含内容**:
- **types/**: TypeScript 类型定义（订阅、节点、配置等）
- **utils/**: 通用工具函数（格式化、验证、存储等）
- **constants/**: 常量定义（API 端点、配置常量等）
- **hooks/**: 共享的 React Hooks（仅在 React 项目中使用）

**设计原则**:
- 平台无关，不依赖特定框架特性
- 使用 TypeScript 编写，提供完整类型定义
- 可以被 Web 和 Desktop 项目直接引用
- 通过 package.json 作为本地 npm 包使用

**引用方式**:
```json
// web/package.json 或 desktop/package.json
{
  "dependencies": {
    "@prism/shared": "workspace:*"
  }
}
```

#### web/
**用途**: Web 前端应用（Next.js）

**功能模块**:
- **订阅管理**: 添加、编辑、删除、更新订阅
- **节点管理**: 查看节点列表、测试延迟、检测解锁能力
- **系统设置**: 代理配置、路由规则、主题设置

**技术栈**:
- **框架**: Next.js 14+ (App Router)
- **语言**: TypeScript
- **包管理器**: pnpm
- **UI 组件库**:
  - Ant Design 5.x（基础组件）
  - **ProComponents**（优先使用，高级业务组件）
    - ProTable（表格）
    - ProForm（表单）
    - ProLayout（布局）
    - ProCard（卡片）
- **状态管理**: Zustand / Redux Toolkit
- **数据请求**: SWR / TanStack Query
- **样式方案**: CSS Modules / Tailwind CSS

**开发命令**:
```bash
# 安装依赖
cd web/frontend && pnpm install

# 开发模式
pnpm dev

# 构建生产版本
pnpm build

# 启动生产服务器
pnpm start
```

#### desktop/
**用途**: 桌面应用程序（Tauri）

**特性**:
- 跨平台支持（Windows、macOS、Linux）
- 系统托盘集成
- 开机自启动
- 本地配置管理
- 与后端服务通信（通过 Tauri Commands）
- 轻量级（相比 Electron 更小的安装包）

**技术栈**:
- **后端**: Tauri 1.x (Rust)
- **前端**: React + TypeScript
- **UI 库**: Ant Design
- **构建工具**: Vite
- **包管理**: pnpm (前端) + Cargo (Rust)

**开发命令**:
```bash
# 安装依赖
cd desktop && pnpm install

# 开发模式（启动 Tauri 开发服务器）
pnpm tauri dev

# 构建应用
pnpm tauri build

# 构建特定平台
pnpm tauri build --target x86_64-pc-windows-msvc  # Windows
pnpm tauri build --target x86_64-apple-darwin      # macOS Intel
pnpm tauri build --target aarch64-apple-darwin     # macOS Apple Silicon
pnpm tauri build --target x86_64-unknown-linux-gnu # Linux
```

#### prism/
**用途**: 可被外部引用的公共包
**包含**:
- 数据模型定义（ModelSubscription、ModelNode等）
- 错误码定义（ErrCode*）
- 公共常量和类型

**原则**:
- 不包含具体实现
- 只定义接口和类型
- 保持稳定的 API

#### internal/
**用途**: 内部实现，外部无法引用
**优势**:
- 封装实现细节
- 避免 API 滥用
- 允许自由重构

### 2.2 业务层目录

#### internal/state/
**职责**: 全局状态管理
- 配置加载
- 数据库连接
- 日志初始化
- 全局变量管理

#### internal/cache/
**职责**: 缓存系统实现
- 统一缓存接口
- 多后端实现（Memory、LevelDB、BBolt、Redis）
- LRU 淘汰策略
- TTL 过期机制

#### internal/service/
**职责**: 业务逻辑实现
**子模块**:
- `subscription/`: 订阅管理（获取、解析、更新）
- `node/`: 节点管理（测试、选择、熔断）
- `route/`: 路由引擎（规则匹配、Trie树）
- `proxy/`: 代理核心（隧道、会话、连接池）
- `task/`: 任务管理（队列、调度、Worker）

#### internal/api/
**职责**: HTTP API 实现
- 路由配置
- 中间件链
- 请求处理器
- 参数验证
- 响应封装

### 2.3 公共包目录

#### pkg/
**用途**: 可被外部项目引用的公共包
**原则**:
- 高度独立
- 无内部依赖
- 文档完善

**子包**:
- `parser/`: 订阅解析器（Clash、V2Ray、Surge）
- `protocol/`: 协议实现（SOCKS5、HTTP、VMess）

### 2.4 配置和数据

#### config/
配置文件存放目录
- `config.yaml`: 主配置文件
- `config.example.yaml`: 配置模板
- `routes.yaml`: 路由规则

#### data/
运行时数据目录（.gitignore）
- SQLite 数据库文件
- 缓存文件
- 临时文件

#### logs/
日志文件目录（.gitignore）

### 2.5 测试目录

## 三、代码组织原则

### 3.1 包命名规范

```go
// ✅ 好的包名
package cache
package service
package handler

// ❌ 差的包名
package cacheUtil
package serviceImpl
package handlerPackage
```

### 3.2 文件命名规范

```
功能.go          # 主实现
功能_test.go     # 单元测试
```

示例:
```
cache/
├── cache.go          # 缓存接口
├── memory.go         # 内存实现
├── memory_test.go    # 内存测试
├── leveldb.go        # LevelDB 实现
└── leveldb_test.go   # LevelDB 测试
```

### 3.3 依赖方向

```
┌──────────────────────────────────────────┐
│              前端层                       │
│  ┌──────────┬──────────┬──────────┐     │
│  │   web/   │  desktop │  mobile  │     │
│  │          │          │  (可选)  │     │
│  └────┬─────┴─────┬────┴─────┬────┘     │
│       │           │          │          │
│       └───────────┼──────────┘          │
│                   │                     │
│                   ▼                     │
│            ┌─────────────┐              │
│            │   shared/   │  前端共享代码 │
│            └─────────────┘              │
│                   │                     │
│                   ▼                     │
│            ┌─────────────┐              │
│            │ HTTP API    │              │
│            └─────────────┘              │
└──────────────────┬────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────┐
│              后端层                       │
│  ┌─────────────┐                         │
│  │ cmd/server  │  程序入口               │
│  └──────┬──────┘                         │
│         │                                │
│         ▼                                │
│  ┌─────────────┐                         │
│  │   internal  │  内部实现               │
│  │   ├─ api    │                         │
│  │   ├─ service│                         │
│  │   └─ state  │                         │
│  └──────┬──────┘                         │
│         │                                │
│         ▼                                │
│  ┌─────────────┐                         │
│  │    prism    │  公共类型               │
│  └─────────────┘                         │
│         │                                │
│         ▼                                │
│  ┌─────────────┐                         │
│  │     pkg     │  可复用包               │
│  └─────────────┘                         │
└──────────────────────────────────────────┘
```

**原则**:
- **前端层**:
  - web/ 和 desktop/ 都依赖 shared/ 共享代码
  - 前端通过 HTTP API 与后端通信，不直接依赖后端代码
  - web/ 和 desktop/ 之间相互独立
- **后端层**:
  - 上层可以依赖下层
  - 下层不能依赖上层
  - 同层之间谨慎依赖

### 3.4 循环依赖避免

❌ **错误示例**:
```
service/subscription → service/node
service/node → service/subscription
```

✅ **正确方法**:
1. 提取公共接口到独立包
2. 使用依赖注入
3. 使用事件总线
