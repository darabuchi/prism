# prism 代理客户端 - 产品设计文档

## 概述

prism 是一款智能代理客户端系统，提供自动化的代理节点管理、全面的性能测试、智能路由选择和订阅管理功能。系统持续监控代理节点性能，根据多项指标自动选择最优节点，通过多种协议提供无缝的代理访问服务。

---

## 平台支持与部署方式

Prism 支持多平台多种部署方式，满足不同用户的使用场景需求。

### Web 服务端部署

支持在各种服务器环境中部署 Web 服务：

**操作系统支持**：
- **Windows Server**：Windows Server 2016/2019/2022，支持 x86_64 架构
- **macOS**：macOS 10.15+，支持 Intel (x86_64) 和 Apple Silicon (ARM64)
- **Linux**：
  - Ubuntu 18.04/20.04/22.04 LTS
  - Debian 10/11/12
  - CentOS 7/8/Stream
  - Rocky Linux 8/9
  - Alpine Linux 3.15+
  - 支持 x86_64、ARM64、ARMv7 架构
- **树莓派**：
  - Raspberry Pi 3/4/5
  - Raspberry Pi OS (32-bit/64-bit)
  - Ubuntu Server for Raspberry Pi

**容器化部署**：
- **Docker**：
  - 提供官方 Docker 镜像
  - 支持 docker-compose 一键部署
  - 多架构镜像支持：linux/amd64, linux/arm64, linux/arm/v7
  - 轻量级 Alpine 基础镜像，体积小巧
- **Kubernetes**：
  - 提供 Helm Chart
  - 支持水平扩展
  - 配置文件和数据持久化
- **Docker Swarm**：支持集群模式部署

**部署特性**：
- 单一二进制文件，无外部依赖
- 自带 Web UI，无需单独部署前端
- 支持 systemd/supervisor 等进程管理器
- 内置数据库（SQLite），开箱即用
- 可选外部数据库（MySQL/PostgreSQL）用于企业级部署

## 一、应用生命周期

### 1.1 启动流程

应用遵循结构化的初始化顺序：

**第一阶段：环境准备**
- 展示应用横幅和版本信息
- 根据命令行标志配置调试或详细模式
- 创建资源目录（如果不存在）
- 初始化和配置日志系统

**第二阶段：状态加载**
- 建立数据库连接（支持 SQLite 或 MySQL）
- 从持久化存储加载配置信息
- 使用 BBolt 嵌入式数据库初始化缓存系统
- 注册 API 路由

**第三阶段：核心服务初始化**
- 创建和初始化代理隧道
- 配置增强型 DNS 解析器
- 加载用于地理路由的 GeoIP 数据库
- 初始化带流量分类规则的规则引擎
- 配置 TUN 接口（特定平台）
- 集成系统代理（可选，依赖平台）

**第四阶段：后台服务**
- 初始化任务队列系统
- 启动基于 cron 触发器的定时任务调度器
- 启动实时更新的 WebSocket 事件系统
- 执行节点和订阅唤醒例程

**第五阶段：API 服务器**
- HTTP/WebSocket 服务器在配置的端口上开始监听
- API 端点可供前端通信使用
- 开始实时统计跟踪

### 1.2 关闭流程

应用通过注册的清理处理程序执行优雅关闭：
- 恢复系统代理设置（如果已启用）
- 关闭活动连接
- 关闭调度器以停止所有定时任务
- 优雅关闭 API 服务器
- 关闭数据库连接
- 同步和清理缓存

## 二、订阅系统

### 2.1 订阅生命周期

#### 添加订阅

用户可以通过多种方式添加代理订阅：

- **HTTP/HTTPS URL**：来自代理提供商的标准订阅链接
- **直接节点配置**：原始代理节点配置字符串
- **批量导入**：多个订阅 URL 用换行符分隔

添加订阅时：
1. 使用 URL 的 SHA256 哈希生成唯一键
2. 重复检测防止添加相同订阅
3. 初始代理类型配置（自动/直连/代理）
4. 立即以高优先级排队更新任务
5. 订阅默认标记为启用状态

#### 订阅更新过程

系统在预定间隔自动更新订阅：

1. **获取阶段**：
   - 使用标识为兼容 Clash 客户端的 user-agent 发起 HTTP 请求
   - 代理类型选择（直连、代理或自动）决定请求路由
   - 解析响应头以获取订阅信息
   - 分析 Content-Disposition 头以获取订阅标题
   - 解析 Subscription-Userinfo 头以获取数据使用统计

2. **解析阶段**：
   - 支持多种格式：Clash YAML、V2Ray 链接、纯文本节点
   - Clash 格式：包含代理部分的 YAML 文档
   - V2Ray 格式：Base64 编码的代理链接
   - 逐行解析支持混合格式
   - 协议检测：SS、SSR、VMess、VLess、Trojan、Hysteria 等

3. **节点存储**：
   - 根据配置为每个节点分配唯一键
   - 以 Base64 编码的 JSON 格式存储节点原始配置
   - 提取和索引节点类型、名称和地址
   - 建立订阅与节点之间的关系
   - 跨订阅合并重复节点

4. **后处理**：
   - 更新订阅信息（流量、到期、标题）
   - 计算下次更新时间（默认：6 小时）
   - 成功更新后重置死亡计数
   - 为每个新节点排队延迟检查任务

#### 订阅信息跟踪

系统跟踪全面的订阅指标：

- **流量统计**：上传、下载、总使用量
- **账户信息**：总分配、已用量、剩余量
- **到期跟踪**：订阅过期时间戳
- **更新历史**：上次更新时间、更新次数
- **节点统计**：发现的总节点数、活动节点数
- **失败跟踪**：用于自动禁用的连续失败计数

### 2.2 订阅管理功能

#### 自动禁用无效订阅

启用后，系统自动禁用以下订阅：
- 配置的最大重试次数后仍未能更新（默认：5 次尝试）
- 重复返回无效或空内容
- 根据订阅信息已过期
- 已超出数据分配限制

#### 手动订阅控制

用户可以手动：
- 启用/禁用订阅以控制节点可用性
- 绕过计划强制立即更新订阅
- 编辑订阅 URL 和代理类型设置
- 查看详细的订阅信息和统计数据
- 删除订阅及其关联节点

#### 订阅共享

启用共享功能后：
- 订阅可以标准 Clash 格式导出
- 活动节点格式化以兼容外部客户端
- 订阅端点提供实时节点列表
- 流量统计嵌入订阅头中
- 支持多种客户端格式（Clash、Meta、Mihomo、V2Ray）

## 三、节点管理

### 3.1 节点发现与存储

#### 节点注册

从订阅中发现节点时：

1. **唯一标识**：完整节点配置的 SHA256 哈希
2. **类型分类**：检测到的协议类型（Shadowsocks、Trojan、VMess 等）
3. **配置持久化**：存储原始配置以便重建
4. **关系映射**：与订阅的多对多关系
5. **初始状态**：所有节点以未检查状态开始，测试待定

#### 节点状态

节点维护几个关键状态：

- **存活状态**：节点是否通过最近的连接测试
- **禁用状态**：手动或自动排除使用
- **健康状态**：熔断器状态（打开、半开、关闭）
- **检查时间戳**：每种测试类型的最后和下次计划测试时间
- **测试结果**：所有性能指标的最新测量值

### 3.2 节点激活系统

#### 活动节点选择

系统基于以下条件维护活动节点池：

1. **评分排名**：按计算的性能评分排序节点
2. **存活过滤**：仅通过连接测试的节点
3. **数量限制**：可配置的最大活动节点数（默认：10）
4. **动态重载**：每 5 分钟自动刷新
5. **手动刷新**：立即重载的 API 端点

#### 节点池管理

活动节点：
- 保存在内存中以便快速访问
- 按评分降序排序
- 与现有节点合并以保留状态
- 根据性能变化轮换
- 禁用或死亡时自动清除

### 3.3 节点禁用逻辑

#### 自动禁用

以下情况节点自动禁用：
- 连续失败的延迟测试超过阈值
- 无法解析节点配置
- 被订阅清理标记为禁用
- 父订阅被禁用
- 协议类型变为不支持

#### 手动禁用

用户可以禁用节点以：
- 排除表现不佳的节点
- 防止使用特定节点
- 临时移除节点而不删除
- 保留节点配置以供将来使用

#### 重新启用过程

禁用的节点可以重新启用：
- 通过 API 端点手动启用
- 如果订阅重新添加则自动启用
- 清除失败计数器后
- 配置修复后

## 四、节点测试系统

### 4.1 延迟测试

#### 测试方法

延迟测试测量节点响应速度：

1. **测试目标**：向 https://www.google.com/generate_204 发起 HTTP HEAD 请求
2. **多次采样**：每次检查进行 10 次连续测试
3. **TLS 握手**：包含完整的 TLS 协商时间
4. **超时处理**：超时的测试标记为失败
5. **统计分析**：从成功测试中计算最小值、最大值和平均值

#### 测试调度

延迟测试以可配置的间隔运行：
- **默认间隔**：存活节点 10 分钟
- **退避策略**：失败的节点使用指数退避测试
- **死亡计数器**：跟踪连续失败
- **延长延迟**：死节点检查频率降低（乘以死亡计数）
- **强制测试**：手动触发绕过调度

#### 结果解释

延迟测试结果决定：
- 节点存活状态（任何成功测试 = 存活）
- 存储用于评分算法的平均延迟
- 首次成功时记录首次存活时间戳
- 每次成功时更新最后存活时间戳
- 根据结果计算下次测试时间

### 4.2 速度测试

#### 下载速度测量

下载测试评估吞吐能力：

1. **测试提供商**：支持多个后端：
   - **Ookla**：标准 speedtest.net 基础设施
   - **Cloudflare**：基于 CDN 的速度测量
   - **LibreSpeed**：开源速度测试
   - **自定义 URL**：HTTP/HTTPS 文件下载

2. **测试配置**：
   - 默认大小：10MB 测试文件
   - 通过设置可配置测试 URL
   - 多次尝试以保证一致性
   - 记录峰值速度作为节点能力

3. **调度策略**：
   - 仅在白天时段（上午 8 点至下午 6 点）运行，除非强制
   - 开始前检查当前网络使用情况
   - 如果网络速度超过 200KB/s 则跳过以避免干扰
   - 默认间隔：1 个月（44,640 分钟）
   - 需要明确启用的可选功能

#### 上传速度测量

上传测试遵循类似方法：
- 兼容测试提供商支持
- 相同的调度和干扰避免
- 与下载指标分开存储
- 目前可选且较少使用

#### 速度测试结果

速度测量影响：
- 节点评分算法显著
- 在节点列表中以人类可读格式显示
- 带宽密集型流量的决策制定
- 性能趋势的历史跟踪

### 4.3 解锁检测测试

#### 流媒体服务检测

系统测试节点访问地理限制内容的能力：

**支持的服务**：

1. **OpenAI**：测试访问 ChatGPT 和 API 端点
   - 检测完全解锁、部分访问或阻止
   - 对 AI 服务路由决策至关重要

2. **Netflix**：验证流媒体服务可用性
   - 测试原创内容可访问性
   - 识别区域库访问

3. **YouTube**：检查视频流能力
   - 验证内容交付
   - 检测高级内容访问

4. **Disney+**：测试 Disney Plus 平台访问
   - 验证区域内容可用性
   - 对家庭娱乐路由重要

**解锁级别分类**：

- **完全（级别 3）**：无限制的完全访问
- **警告（级别 2）**：检测到部分访问或警告
- **禁止（级别 1）**：服务明确阻止或拒绝
- **无（级别 0）**：未测试或测试不确定

**测试调度**：
- 默认间隔：1 个月（44,640 分钟）
- 仅测试存活节点
- 需要启用的可选功能
- 结果影响特定服务的节点选择

**对路由的影响**：
- 具有解锁能力的节点优先用于匹配服务
- OpenAI 目标路由到 OpenAI 解锁节点
- Netflix 流量定向到 Netflix 能力节点
- 如果没有解锁节点则自动回退

### 4.4 地理位置检测

#### IP 信息收集

系统确定节点地理属性：

**入站检测**（入口点）：
1. 节点主机名的 DNS 解析
2. 通过 ipinfo.io 进行 IP 地址地理定位
3. 提取：
   - 国家代码和名称
   - ASN 编号和组织
   - ISP 识别
   - 时区信息

**出站检测**（出口点）：
1. 通过节点代理请求 ipinfo.io
2. 发现节点的出口 IP 地址
3. 捕获相同的地理属性
4. 启用路由质量分析

**数据提供商**：
- 主要：ipinfo.io API，提供全面数据
- 次要：美团位置服务（中国）
- 可靠性的回退机制

**用例**：
- 根据入口/出口不匹配对节点评分
- 地理路由以匹配目的地
- ISP 和网络质量评估
- 路由优化决策

### 4.5 IP 风险评估

#### 风险评估

系统分析 IP 信誉和风险因素：

**检测的风险类别**：
- VPN/代理检测评分
- 威胁级别评估
- 匿名代理识别
- 数据中心托管检测
- 已知攻击者标记
- 滥用历史跟踪

**风险级别**：
- **高**：危险或受损的 IP
- **中**：检测到可疑活动
- **低**：存在轻微风险指标
- **安全**：验证清洁声誉

**数据源**：
- IPData.co 提供全面的威胁情报
- Whoer.net 提供匿名性评分
- 多个黑名单交叉引用
- ASN 声誉数据库

**对选择的影响**：
目前仅供参考，用于：
- 未来的过滤能力
- 用户对节点质量的认识
- 潜在的自动排除
- 基于风险的路由决策

### 4.6 路由质量测试

#### Traceroute 分析

系统执行网络路径分析：

1. **路径发现**：
   - Traceroute 到节点的 IP 地址
   - 逐跳延迟测量
   - 路由稳定性评估
   - 网络路径识别

2. **质量确定**：
   - 检查高级网络路径
   - 识别直接与拥塞路由
   - 检测骨干网络使用
   - 测量路径一致性

3. **高质量路由标准**：
   - 存在一级提供商网络
   - 到目的地的最小跃点数
   - 跃点间的低延迟变化
   - 避免已知拥塞点

**测试调度**：
- 默认间隔：1 周（10,080 分钟）
- 仅用于存活节点
- 需要启用的可选功能
- 资源密集型，谨慎调度

**结果应用**：
- 为高级路径设置高质量路由标志
- 评分算法中的显著奖励
- 存储列出的路由跳数以供分析
- 用于网络质量差异化

#### 证书管理

**CA 证书生成**：
```
初始化时：
1. 生成 RSA 2048 位私钥

3. 保存到配置目录（$HOME/.prism/ca.crt 和 ca.key）

```

```
2. 如未缓存，使用 CA 签发域名证书
3. 设置合适的有效期（默认 1 年）
4. 缓存证书供后续使用
5. 证书包含完整的 SAN（主题备用名称）
```

**证书安装指导**：
- macOS：系统钥匙串访问导入

#### 安全考虑

**隐私保护**：

**兼容性**：
- 某些应用启用证书固定（Certificate Pinning）会失败
- 提供检测和提示机制
- 支持按进程禁用 MITM
- 双向认证（mTLS）场景需特殊处理

**合规性**：
- 仅用于个人调试和开发目的
- 不得用于拦截他人通信
- 企业环境需遵守相关政策
- 记录和日志需妥善管理

### 5.3 熔断器实现

#### 健康状态管理

每个节点维护熔断器状态：

**状态**：

1. **打开（健康）**：
   - 节点接受所有连接尝试
   - 成功率达到阈值要求
   - 充分参与节点选择

2. **半开（降级）**：
   - 允许有限的连接尝试
   - 探测恢复潜力
   - 减少选择参与

3. **关闭（不健康）**：
   - 节点暂时从选择中排除
   - 检测到最近失败过多
   - 定期探测尝试继续

**状态转换**：

- **打开 → 关闭**：当失败率超过阈值时：
  - 20 次总请求成功率低于 60%
  - 50 次总请求成功率低于 70%
  - 100 次总请求成功率低于 80%
  - 更多请求成功率低于 90%
  - 或 3 次以上连续失败

- **关闭 → 半开**：超时期后且探测成功

- **半开 → 打开**：成功率提高时

- **半开 → 关闭**：如果失败继续

**配置**：
- 时间窗口：5 分钟滚动窗口
- 缓冲区大小：跟踪 200 个最近请求
- 探测机会：关闭时 10% 概率
- 基于请求量的动态阈值

### 5.4 会话管理

#### 粘性会话

系统维护连接持久性：

1. **会话密钥生成**：
   - 基于通用流量的目标主机
   - 基于特定服务（OpenAI、Cloudflare）的目标类型
   - 每个逻辑连接组唯一

2. **会话存储**：
   - 带有 300 秒老化的 LRU 缓存
   - 最多跟踪 128 个会话
   - 每次访问时更新年龄
   - 自动过期和清理

3. **会话优势**：
   - 多请求操作的一致 IP
   - 减少连接建立开销
   - 有状态协议的更好性能
   - 提高用户体验一致性

#### 阻止列表管理

失败的连接触发临时阻止：

1. **阻止标准**：
   - 建立期间连接失败
   - 握手超时或错误
   - 特定协议失败
   - TLS 证书问题

2. **阻止存储**：
   - 带有 60 秒老化的 LRU 缓存
   - 最多 32 个被阻止的会话-节点对
   - 按会话 + 节点唯一 ID 键入
   - 自动过期无需续订

3. **阻止效果**：
   - 在被阻止会话的选择期间跳过节点
   - 防止立即重试失败的组合
   - 超时后允许恢复
   - 不影响节点的全局可用性

### 5.5 流量统计

#### 实时监控

系统跟踪全面的连接指标：

1. **连接计数**：
   - 总活动连接

   - 每个目标类型的连接

### 6.2 规则匹配过程

#### 优先级顺序

1. **自定义规则**（最高优先级）：
   - 来自配置的用户定义规则
   - 在所有其他规则之前首先检查
   - 允许覆盖内置规则

2. **域 Trie 查找**：
   - 快速前缀树匹配
   - 高效处理通配符
   - 域后缀匹配
   - 关键字扩展模式

3. **IP 范围匹配**：
   - CIDR 块评估
   - 私有网络检测
   - 地理 IP 匹配
   - 基于 ASN 的路由

4. **内置规则**（基于文件）：
   - 从 proxy.pb 文件加载
   - 包含广泛的域名/IP 列表
   - 按服务和目标分类
   - 定期更新规则集

5. **默认规则**（最低优先级）：
   - 捕获所有不匹配的流量
   - 默认为代理路由
   - 确保没有流量未处理

#### 优化技术

- **Trie 数据结构**：域名的 O(m) 查找，其中 m 是域名长度
- **反向优先级处理**：规则以相反顺序处理以填充 trie
- **IP CIDR 树**：IP 范围的快速包含检查
- **模式预编译**：正则表达式编译一次
- **缓存预热**：频繁访问的规则保持热态

- 类型和目标兼容性
- 负载格式正确性
- 正则表达式语法
- IP CIDR 表示法有效性
- 没有冲突规则

规则可以在不重启的情况下更新：
- API 端点触发重新加载

- 原子替换旧结构

### 7.2 选择策略

#### 粘性会话策略

维护连接持久性：
- 检查会话缓存中的先前节点
- 如果仍然有效则返回缓存的节点
- 如果节点不可用或失败则穿透
- 非常适合多请求操作

#### 随机范围策略

带过滤的平衡随机选择：
- 在节点列表中的随机位置开始
- 遍历所有节点一次
- 对每个候选应用过滤器检查
- 返回第一个通过的节点
- 确保公平分配

#### 弱随机范围策略

基于映射的随机选择：
- 遍历节点映射（无序）
- 应用过滤器检查
- 返回第一个有效节点
- 更不可预测的顺序
- 适合发现

#### 随机一个策略

纯随机选择：
- 选择完全随机的节点
- 不应用过滤
- 用于测试或回退
- 最大不可预测性

#### 范围策略

基于评分的顺序选择：
- 按评分顺序遍历节点
- 返回评分最高的有效节点
- 应用过滤器检查
- 最佳性能优先级

### 7.3 过滤器检查

#### 阻止会话检查

防止立即重试失败：
- 检查会话-节点对是否最近失败
- 如果在阻止列表中则返回 false
- 超时到期后允许重试
- 减少浪费的连接尝试

#### 请求前检查（熔断器）

评估节点健康状态：
- 调用熔断器的 Before() 方法
- 尊重打开/半开/关闭状态
- 为关闭的节点实现探测逻辑
- 主要可靠性机制

#### 解锁检查

验证服务可访问性：
- 仅与特定服务目标相关
- 检查 OpenAI 目标的 OpenAI 标志
- 检查 Netflix 目标的 Netflix 标志
- 检查 Disney 目标的 Disney 标志
- 对通用代理目标返回 true

#### 总请求检查

限制节点负载：
- 检查熔断器请求计数器
- 与配置的阈值比较
- 防止热门节点过载
- 启用负载分配

#### 国家检查

地理匹配：
- 比较节点出口国家与目的地
- 对区域内容访问有用
- 减少地理临近流量的延迟
- 可选优化

### 7.4 评分算法

#### 默认评分公式

节点根据多个因素获得评分：

**基础评分计算**：
- 从 0 分开始

**延迟组件**（主要因素）：
- 公式：(1 - delay/10000) × 10
- 较低延迟 = 较高评分
- 100ms 延迟 = ~9.9 分
- 1000ms 延迟 = ~9 分
- 限制贡献

**速度组件**（显著）：
- 公式：download / 50MB
- 50MB/s = 1 分
- 100MB/s = 2 分
- 直接成比例

**协议类型奖励**：
- Shadowsocks：+3 分（最快）
- Trojan：+2 分（平衡）
- VMess：+1 分（功能丰富）

**解锁能力奖励**：
- 每个解锁服务：+0.025 分
- OpenAI 解锁：+0.025
- Netflix 解锁：+0.025
- YouTube 解锁：+0.025
- Disney 解锁：+0.025
- 最大组合：+0.1 分

**地理奖励**：
- 入口/出口国家不同：+0.005 分
- 入口/出口国家相同：+0.0025 分
- 奖励多样化路由路径

**路由质量奖励**（显著）：
- 检测到高质量路由：+3 分
- 对选择的主要影响
- 奖励优质网络路径

**惩罚**：
- 出站国家 = CN：-10 分（中国出口惩罚）
- 入站国家 = CN：+3 分（中国入口奖励）
- 死亡或无效节点：-100 分（有效排除）

#### 自定义评分脚本

用户可以提供 JavaScript 评分函数：
- 访问所有节点属性
- 提供数学辅助函数
- 在隔离 VM 中安全执行
- 脚本失败时回退到默认

#### 评分更新触发器

- 任何节点测试完成后
- 手动评分重置操作
- 节点信息更新
- 配置更改

### 7.5 回退行为

#### 选择失败

如果没有节点通过所有检查：

1. 尝试链中的下一个选择策略
2. 放松某些过滤器要求
3. 允许半开熔断器节点
4. 跳过地理匹配
5. 使用完全随机选择
6. 最终回退：使用直连

#### 死节点池处理

死节点保留在数据库中但：
- 从活动节点池中排除
- 不考虑选择
- 保留以供潜在恢复
- 可以手动重新启用
- 通过测试后自动恢复

### 10.2 任务队列系统

#### 队列架构

系统使用带持久化的内存消息队列：

1. **消息结构**：
   - 任务类型标识符
   - 实体 ID（订阅、节点）
   - 优先级的强制标志
   - 可选数据负载

2. **优先级级别**：
   - 高：用户发起的操作
   - 正常：计划任务
   - 低：后台维护

3. **处理**：
   - 用于并行执行的工作池
   - 任务处理程序注册
   - 错误处理和重试
   - 执行日志

4. **任务类型**：
   - UpdateSubscribe：获取和解析订阅
   - CheckNodeDelay：延迟测试
   - CheckNodeDownload：速度测试
   - CheckNodeUnlock：服务解锁检测
   - CheckNodeRegion：地理位置
   - CheckNodeRoutes：网络路径分析
   - ProxyFastIpDirect：IP 优化

#### 任务执行流程

1. 任务按优先级添加到队列
2. 工作程序从队列中选择任务
3. 按任务类型查找适当的处理程序
4. 处理程序使用超时保护执行
5. 记录成功/失败及指标
6. 持久化结果（如适用）
7. 如果需要，排队依赖任务

#### 并发控制

- 下载测试：互斥锁保护（一次一个）
- 订阅更新：每个订阅互斥锁保护
- 节点测试：并行至工作池大小
- 数据库操作：连接池管理
- 网络测试：速率限制以防止洪水

## 十三、系统行为和业务规则

### 13.1 节点评分优先级

节点根据以下因素评分和选择：
1. 连接性（存活状态）- 消除死节点
2. 延迟（越低越好）- 主要组件
3. 速度（越高越好）- 显著因素
4. 路由质量（优先高级路径）- 大奖励
5. 协议效率（SS > Trojan > VMess）
6. 解锁能力（服务访问）
7. 地理因素（入口/出口多样性）

### 13.2 自动节点选择

对于每个连接，系统：
1. 匹配路由规则以确定目标
2. 按熔断器状态过滤节点
3. 排除最近失败的组合
4. 应用特定服务要求（解锁）
5. 考虑地理匹配
6. 使用配置的策略选择
7. 失败时优雅回退

### 13.3 测试智能

系统优化测试资源：
- 定期测试存活节点
- 使用退避测试死节点（指数延迟）
- 仅在网络空闲时的非高峰期进行速度测试
- 除非强制，否则每月进行解锁测试
- 为节约成本每周进行路由测试
- 除非更改，否则进行一次地理测试

### 13.4 资源保护

系统保护系统资源：
- 如果网络繁忙则跳过速度测试
- 除非强制，否则仅在白天进行速度测试
- 串行下载测试（一次一个）
- 订阅更新速率限制
- 数据库操作优化
- 定期清理内存

### 13.5 数据保留

系统管理数据生命周期：
- 软删除记录保留 1 周
- 宽限期后硬删除
- 24 小时后清理禁用项（可配置）
- 自动删除失败的订阅（可配置）
- 检测和清理孤立数据

### 13.6 连接可靠性

系统确保可靠的连接：
- 熔断器防止不良节点过载
- 阻止列表防止立即重试
- 冗余的多种选择策略
- 优雅回退到直连
- 自动节点池刷新

### 13.7 隐私和安全

系统尊重隐私：
- 所有数据的本地处理
- 无遥测或外部报告
- 用户控制所有功能
- 安全凭证存储
- 明确标记可选功能

### 14.2 当前限制

#### 速度测试
- 仅下载测试（上传有限）
- 时间段限制
- 网络干扰避免
- 资源密集型操作
- 每月默认间隔

#### 地理检测
- 需要外部 API 访问
- 提供商速率限制
- 缓存结果可能过时
- 某些节点可能缺少数据

#### 解锁测试
- 需要特定服务实现
- 检测准确性各异
- 可能产生误报/漏报
- 每月默认间隔

#### 节点选择
- 限于配置的活动节点数
- 熔断器可能暂时排除工作节点
- 阻止列表防止立即重试
- 每个连接不跨多个节点负载平衡

#### 规则匹配
- 进程匹配需要提升权限
- 某些规则特定于平台
- 正则表达式有性能成本
- GeoIP 数据库需要更新

#### 订阅管理
- 某些订阅格式可能无法正确解析
- 不支持身份验证
- 无订阅版本控制
- 提供商的错误详细信息有限

#### 数据保留
- 无自动备份到外部存储
- 数据库大小随历史增长
- 可能需要手动清理
- 无数据导出功能

### 14.3 功能交互

#### 速度测试 + 网络使用
- 如果网络繁忙，速度测试自动跳过
- 用户可以强制测试覆盖

#### 熔断器 + 测试
- 失败的测试计入熔断器
- 熔断器状态不阻止测试
- 测试可以恢复关闭的节点

#### 订阅更新 + 节点测试
- 新节点立即排队进行延迟测试
- 其他测试正常计划
- 更新不中断活动连接

#### 规则更改 + 活动连接
- 新连接立即使用新规则
- 活动连接继续使用旧路由
- 无连接中断

#### 配置更改 + 代理
- 某些更改需要代理重新加载（端口、TUN）
- 重新加载短暂中断新连接
- 活动连接可能得到保留
